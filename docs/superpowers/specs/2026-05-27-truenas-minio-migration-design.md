# Design: TrueNAS + MinIO Migration & Deployment

**Date:** 2026-05-27  
**Status:** Approved  
**Scope:** Migrate storage from Cloudflare R2 to MinIO on TrueNAS, add Docker Compose for self-hosted deployment, update documentation, and produce a TrueNAS deployment guide.

---

## 1. Overview

Bay'sConsult currently uses Cloudflare R2 for file storage. This migration replaces R2 with **MinIO running on TrueNAS** as the primary object storage, while keeping Vercel as the production app host and cloud PostgreSQL (Neon/Supabase) as the primary database.

Two deployment targets will be supported:
- **Vercel** — production, Next.js app deployed to Vercel, connects to MinIO via Cloudflare Tunnel
- **TrueNAS self-hosted** — full Docker Compose stack (Next.js + MinIO + n8n) running on TrueNAS

---

## 2. Architecture

```
Production:
  User Browser → Vercel (Next.js) → Cloud PostgreSQL (Neon/Supabase)
                                  → Cloudflare Tunnel → MinIO on TrueNAS

Self-hosted (TrueNAS):
  User Browser → Next.js (Docker) → Cloud PostgreSQL (Neon/Supabase)
                                  → MinIO (Docker, same host, internal network)
```

MinIO is **never** accessed directly by the browser. All file access goes through signed URLs generated by the Next.js backend after permission checks.

## 3. Section 1 — Storage Migration (R2 → MinIO)

### 3.1 What changes

MinIO is S3-compatible. The AWS SDK code does not change. Only env var names and minor log messages are updated.

**Env var renames:**

| Old (R2) | New (MinIO) |
|---|---|
| `R2_ACCESS_KEY_ID` | `MINIO_ACCESS_KEY_ID` |
| `R2_SECRET_ACCESS_KEY` | `MINIO_SECRET_ACCESS_KEY` |
| `R2_ENDPOINT` | `MINIO_ENDPOINT` |
| `R2_BUCKET_NAME` | `MINIO_BUCKET_NAME` |
| `R2_PUBLIC_URL` | `MINIO_PUBLIC_URL` |

### 3.2 File changes

**`src/lib/s3.ts`**
- Rename all `R2_*` env var references to `MINIO_*`
- Change `region: "auto"` to `region: "us-east-1"` (MinIO does not support `"auto"`; the value is ignored with `forcePathStyle: true` but must be a valid string)
- Update error messages to say "MinIO" instead of "Cloudflare R2"
- Keep `forcePathStyle: true` — required for MinIO

**`src/app/api/upload/route.ts`**
- Update log messages that reference "R2 bucket" and "R2 Upload Route Error"

**`src/app/api/documents/presigned/route.ts`**
- Update `R2_PUBLIC_URL` env var reference to `MINIO_PUBLIC_URL`

**`.env.example`** (new file)
- Template with all env vars and no secret values
- Committed to git as deployment reference

**`CLAUDE.md`**
- Update Required Environment Variables section: R2_* → MINIO_*
- Add Docker section

## 4. Section 2 — Docker Compose

### 4.1 `docker-compose.yml` — TrueNAS production stack

Runs with `docker compose up -d`. Contains:

- **`app`** — Next.js, built from `Dockerfile`, port 3000, reads `.env.production`, depends on `minio`
- **`minio`** — MinIO latest, ports 9000 (API) and 9001 (Console), bind mount to `./truenas-data/minio:/data`
- **`n8n`** — existing config, unchanged

MinIO uses a **bind mount** (not a named volume) so data lives in a TrueNAS dataset path that can be backed up via TrueNAS snapshot or rsync.

### 4.2 `docker-compose.dev.yml` — local dev overrides

Runs with `docker compose -f docker-compose.dev.yml up -d`. Contains:

- **`postgres`** — postgres:16-alpine, port 5433, named volume `postgres_dev_data`
- **`minio`** — MinIO for local testing, named volume `minio_dev_data`, dev credentials

Developers running `npm run dev` do not need this file unless they want a local MinIO for file upload testing.

### 4.3 `Dockerfile` — Next.js production build

Multi-stage build:
1. **builder** stage — `node:20-alpine`, installs deps, runs `prisma generate`, runs `next build`
2. **runner** stage — copies `.next/standalone`, static files, and `public/`

`output: "standalone"` sudah ada di `next.config.mjs`. Perlu update `images.remotePatterns`: ganti hostname R2 (`pub-xxx.r2.dev`) dengan hostname MinIO (`s3.yourdomain.com`).

**`.dockerignore`** (new) — excludes `node_modules`, `.next`, `.env*`, `truenas-data`.

## 5. Section 3 — Cloudflare Tunnel

### 5.1 Subdomains

| Subdomain | Target | Purpose |
|---|---|---|
| `s3.yourdomain.com` | `http://localhost:9000` | MinIO API — used by Vercel |
| `console.yourdomain.com` | `http://localhost:9001` | MinIO Console — private access only |

### 5.2 Setup

Cloudflare Tunnel is installed on TrueNAS (via TrueNAS App Catalog or `cloudflared` binary), **not** as a Docker Compose service. This is more stable and survives Docker restarts.

Tunnel config routes `s3.yourdomain.com` → MinIO API port 9000.

### 5.3 Env vars by environment

**Vercel (production):**
```
MINIO_ENDPOINT=https://s3.yourdomain.com
MINIO_ACCESS_KEY_ID=<minio-app-access-key>
MINIO_SECRET_ACCESS_KEY=<minio-app-secret>
MINIO_BUCKET_NAME=baysconsult-docs
```

**TrueNAS self-hosted (`.env.production`):**
```
MINIO_ENDPOINT=http://minio:9000
MINIO_ACCESS_KEY_ID=<minio-app-access-key>
MINIO_SECRET_ACCESS_KEY=<minio-app-secret>
MINIO_BUCKET_NAME=baysconsult-docs
```

The self-hosted app uses the Docker internal network hostname `minio` directly — no tunnel needed.

## 7. Section 5 — TrueNAS Deployment Guide

Saved at `docs/deployment/truenas.md`. Covers five phases:

### Phase 1 — Persiapan TrueNAS
1. Buat dataset di TrueNAS pool: `POOL/apps/baysconsult` dan `POOL/apps/baysconsult/minio-data`
2. Pastikan Docker / TrueNAS Apps aktif
3. Clone repo: `git clone ... /mnt/POOL/apps/baysconsult/app`

### Phase 2 — Setup MinIO
1. Buat folder bind mount: `mkdir -p truenas-data/minio`
2. Jalankan MinIO saja: `docker compose up -d minio`
3. Buka MinIO Console: `http://<truenas-ip>:9001`
4. Buat bucket `baysconsult-docs` (private, tidak public)
5. Buat service account / access key untuk app
6. Test upload manual dari console

### Phase 3 — Cloudflare Tunnel
1. Install Cloudflare Tunnel dari TrueNAS App Catalog
2. `cloudflared tunnel login` dan `cloudflared tunnel create baysconsult`
3. Config ingress: `s3.yourdomain.com → http://localhost:9000`
4. Add DNS CNAME di Cloudflare dashboard
5. Test: `curl https://s3.yourdomain.com/minio/health/live` → harus return `200`

### Phase 4 — Deploy Next.js App (TrueNAS)
1. Buat `.env.production` dari `.env.example` (isi semua nilai)
2. `docker compose up -d app`
3. Jalankan migrasi: `docker compose exec app npx prisma migrate deploy`
4. Buka `http://<truenas-ip>:3000`
5. Test upload dan download dokumen

### Phase 5 — Vercel Production
1. Di Vercel dashboard → Settings → Environment Variables
2. Set semua `MINIO_*` vars (endpoint = `https://s3.yourdomain.com`)
3. Set `DATABASE_URL` ke Neon/Supabase connection string
4. Redeploy
5. Test upload dari production app ke MinIO TrueNAS

## 9. Out of Scope

- Multi-tenancy refactor (tenant_id isolation) — sudah ada di arsitektur doc sebagai future work
- Presigned upload URL (direct browser → MinIO) — current server-side upload tetap dipakai untuk MVP
- MinIO bucket versioning — bisa diaktifkan manual di MinIO console, tidak perlu kode
- Backup automation (rsync / snapshot schedule) — dikonfigurasi di TrueNAS UI, bukan di codebase
